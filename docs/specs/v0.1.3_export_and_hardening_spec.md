# VORTEX (CreatorVault) v0.1.3 — Direct File Export & System Hardening Specification

This document details the planned modifications for Vortex v0.1.3:
1. **Universal Direct-Export Routing**: Export single-file outputs directly to the user's chosen folder without creating redundant subfolders, while retaining dedicated subfolders for multi-file deliverables.
2. **Automatic Collision Numbering**: Append `(1)`, `(2)`, etc. when a file with the same name already exists in the destination folder.
3. **Four Hardening Patches**: Stem WAV leak cleanup, silent video safety check in silence chopper, expanded audio fallback extensions, and expanded unit tests.

---

## 1. Universal Export Routing Rule

### Problem in Current Code
Every module currently creates a dedicated subfolder (`${baseName}_${jobId.slice(0, 6)}`) regardless of whether the job produces 1 file or multiple files. For example, downloading a 15-second video clip creates a folder with a single `.mp4` inside it.

## 2. Automatic Name Collision Resolution

When exporting directly into `config.outputDir`, a file with the target name might already exist (e.g. `Sunset_Clip.mp4`).

### Planned Shared Utility (`electron/services/FileUtils.ts`)
```typescript
import fs from 'node:fs';
import path from 'node:path';

export function getNonCollidingFilePath(destDir: string, baseName: string, ext: string): string {
  const cleanExt = ext.startsWith('.') ? ext : `.${ext}`;
  let candidate = path.join(destDir, `${baseName}${cleanExt}`);
  if (!fs.existsSync(candidate)) {
    return candidate;
  }

  let counter = 1;
  while (fs.existsSync(path.join(destDir, `${baseName} (${counter})${cleanExt}`))) {
    counter++;
  }
  return path.join(destDir, `${baseName} (${counter})${cleanExt}`);
}
```

## 3. Four System Hardening Patches

### Patch A: Stem Separation Temporary WAV Cleanup
- **File:** `electron/services/StemRunner.ts`
- **Issue:** `cleanupTempWav` is only called inside `proc.on('close')`. If Demucs is missing and simulation fallback runs (`runSimulatedStems`), or if Python throws a spawn `error`, `${name}_48k.wav` remains orphaned on disk (leaking 50–150MB per job).
- **Fix:** Move `cleanupTempWav` up to the promise scope, invoke it in `proc.on('error')`, and call it inside `runSimulatedStems` before returning pills.

### Patch B: Silent Video Guard in Silence Chopper
- **File:** `electron/services/FfmpegRunner.ts`
- **Issue:** When `silence-xml` runs on a video without an audio track, FFmpeg fails to attach the `silencedetect` audio filter and exits with code 1 (`Silence scan exited with code 1`).
- **Fix:** Check `config.audioCodec !== 'none'` and verify `hasAudioStream(config.inputPath)` before launching `detectSpeechSegments()`. If no audio exists, reject early with a clear creator message: `Video has no audio track for silence detection`.

### Patch C: Expanded File Finder Audio Extensions
- **File:** `electron/services/YtDlpRunner.ts`
- **Issue:** The fallback file searcher in `jobFolder` checks only `['.mp4', '.mkv', '.webm', '.wav', '.mp3']`. If yt-dlp outputs `.m4a`, `.flac`, `.opus`, or `.ogg`, the file is ignored and an error is thrown.
- **Fix:** Add `.m4a`, `.flac`, `.opus`, and `.ogg` to the extension set.

### Patch D: Test Suite Additions
- **File:** `tests/self-check.test.mjs`
- **Additions:**
  1. Unit tests for `getNonCollidingFilePath` (testing `name.ext` -> `name (1).ext` -> `name (2).ext`).
  2. Unit tests for Premiere Pro XML sequence frame calculation rules.
  3. Unit tests for silence detection edge case guards.

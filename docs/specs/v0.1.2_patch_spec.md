# VORTEX (CreatorVault) v0.1.2 — Execution & Patch Specification

This specification details code modifications and hardening patches for the 6 launch blockers identified in `v0.1.1` and refined during the EGM Goldfish review session.

---

## Fix 1: Correct YouTube 4K/1440p VP9/AV1 Downsample Bug
- **File:** `electron/services/YtDlpRunner.ts`
- **Problem:** `bestvideo[height<=2160][ext=mp4][vcodec^=avc]` matches 1080p for 4K requests because YouTube does not offer 4K in H.264. Simple remuxing (`--remux-video mp4`) copies VP9/AV1 bitstreams without transcoding, breaking NLE import in Premiere Pro and DaVinci Resolve.
- **Solution:** Select the true height stream when `editReadyMode` is active and transcode to standard H.264 MP4 (`--recode-video mp4`). In raw mode, retain untouched source streams in MKV/WebM containers.

### Replacement Instructions:
Inside `executeDownload()` in `electron/services/YtDlpRunner.ts`, update format selection logic:

```typescript
// REPLACE in electron/services/YtDlpRunner.ts inside executeDownload():
    } else {
      const heightMap: Record<string, number> = {
        '4K': 2160,
        '1440p': 1440,
        '1080p': 1080,
        '720p': 720
      };
      const maxH = heightMap[config.quality] || 1080;

      if (config.editReadyMode) {
        // For 4K/1440p, YouTube provides VP9/AV1. Recode to H.264 MP4 so NLEs (Premiere/DaVinci) can import
        if (maxH >= 1440) {
          args.push(
            '-f',
            `bestvideo[height<=${maxH}]+bestaudio/best`,
            '--merge-output-format',
            'mp4',
            '--recode-video',
            'mp4'
          );
        } else {
          args.push(
            '-f',
            `bestvideo[height<=${maxH}][ext=mp4][vcodec^=avc]+bestaudio[ext=m4a]/bestvideo[height<=${maxH}]+bestaudio/best`,
            '--merge-output-format',
            'mp4',
            '--remux-video',
            'mp4'
          );
        }
      } else {
        args.push(
          '-f',
          `bestvideo[height<=${maxH}]+bestaudio/best`,
          '--merge-output-format',
          'mkv'
        );
      }
    }
```

## Fix 2: Prevent Chrome Cookie-Lock Crash on Download
- **File:** `electron/services/YtDlpRunner.ts`
- **Problem:** `probeUrl` catches database locks, but `executeDownload` fails instantly when cookies are locked. Broad matching on generic permission errors caused redundant retries on filesystem write failures.
- **Solution:** Add cancellation guard at entry, narrow lock error matching to cookie database regex, clone config without in-place mutation, and emit progress notice.

### Replacement Instructions:
Update `executeDownload()` entry and `proc.on('close')` error handling:

```typescript
// AT ENTRY OF executeDownload():
    if (this.cancelledJobs.has(jobId)) {
      this.cancelledJobs.delete(jobId);
      throw new Error('Job cancelled by user');
    }

// REPLACE error handling inside proc.on('close'):
        } else {
          const fullErr = stderrLog.trim();
          const isCookieLocked =
            /(cookie.*locked|cannot access.*cookie|Could not copy Chrome cookie database|database is locked)/i.test(
              fullErr
            );

          // Fallback if browser cookie database is locked during download
          if (
            config.browserCookies &&
            config.browserCookies !== 'none' &&
            isCookieLocked
          ) {
            const retryConfig = { ...config, browserCookies: 'none' as const };
            onProgress({
              jobId,
              stage: 'downloading',
              progress: 0,
              statusMessage: 'Browser cookie database locked. Retrying anonymously...'
            });
            // Recursive retry with cookies disabled and cloned config
            this.executeDownload(jobId, retryConfig, onProgress).then(resolve).catch(reject);
            return;
          }
          reject(new Error(fullErr || `yt-dlp exited with code ${code}`));
        }
```

## Fix 3: Safe Node Runtime Execution for YouTube Deciphering
- **File:** `electron/services/YtDlpRunner.ts`
- **Problem:** Hardcoding `--js-runtimes node` crashed when `node.exe` was missing from system `PATH`. Completely removing it exposed YouTube downloads to n-sig speed throttling.
- **Solution:** Probe whether `node` is available on the host system. If available, pass `--js-runtimes node`; otherwise omit gracefully.

### Replacement Instructions:
Add `isNodeAvailable()` helper and conditionally inject `--js-runtimes node` in `runYtDlpProbe()` and `executeDownload()`.

## Fix 4: Streamed, Atomic Standalone `yt-dlp.exe` Downloader
- **File:** `electron/services/BinaryManager.ts`
- **Problem:** `pip install yt-dlp` dropped binaries into hidden script folders. Synchronous direct writing blocked the event loop and crashed with `EBUSY` when files were locked.
- **Solution:** Stream download to a temporary file (`yt-dlp.exe.tmp`), enforce a 60s timeout, verify binary size (>1MB), and atomically replace destination with `fs.renameSync()`.

### Replacement Instructions:
```typescript
      } else if (name === 'yt-dlp') {
        const exeName = process.platform === 'win32' ? 'yt-dlp.exe' : 'yt-dlp';
        const targetPath = path.join(this.binDir, exeName);
        const tempPath = path.join(this.binDir, `${exeName}.tmp_${Date.now()}`);
        const url = process.platform === 'win32'
          ? 'https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp.exe'
          : 'https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp';

        const controller = new AbortController();
        const timer = setTimeout(() => controller.abort(), 60000);

        try {
          const res = await fetch(url, { signal: controller.signal });
          clearTimeout(timer);
          if (!res.ok) throw new Error(`Failed to download yt-dlp binary (${res.status} ${res.statusText})`);
          if (!res.body) throw new Error('Download stream is empty.');

          const fileStream = fs.createWriteStream(tempPath);
          const { Readable } = await import('node:stream');
          const { pipeline } = await import('node:stream/promises');
          await pipeline(Readable.fromWeb(res.body as any), fileStream);

          const stat = fs.statSync(tempPath);
          if (stat.size < 1024 * 1024) {
            try { fs.unlinkSync(tempPath); } catch {}
            throw new Error(`Downloaded yt-dlp binary is incomplete (${Math.round(stat.size / 1024)} KB)`);
          }

          if (process.platform !== 'win32') {
            fs.chmodSync(tempPath, '755');
            if (process.platform === 'darwin') {
              try {
                execFileSync('xattr', ['-d', 'com.apple.quarantine', tempPath], { stdio: 'ignore' });
              } catch {}
            }
          }

          if (fs.existsSync(targetPath)) {
            try {
              fs.unlinkSync(targetPath);
            } catch (unlinkErr) {
              const code = (unlinkErr as any)?.code;
              if (code === 'EBUSY' || code === 'EPERM') {
                throw new Error('yt-dlp binary is currently locked by another process or antivirus. Close active downloads and try again.');
              }
            }
          }
          fs.renameSync(tempPath, targetPath);
        } catch (downloadErr) {
          if (fs.existsSync(tempPath)) {
            try { fs.unlinkSync(tempPath); } catch {}
          }
          throw downloadErr;
        }
```

## Fix 5: Preserve Transparency in Real-ESRGAN Upscaler with Linear Overlap Feathering
- **File:** `electron/services/VectorRunner.ts`
- **Problem:** `.convert('RGB')` destroyed the alpha channel of transparent cutout PNGs produced by `rembg`. Simple tile slicing created visible square grid seam lines across images >640×640 and risked CUDA OOM. FFmpeg fallback `cas` filter crashed on RGBA.
- **Solution:** Separate alpha channel and resize with Lanczos. For RGB, allocate canvas on CPU RAM, apply 2D linear ramp feathering across tile overlap margins to eliminate seams, and use RGBA-safe `unsharp` filter in FFmpeg fallback.

### Replacement Instructions:
Update `runAssetUpscaler()` in `electron/services/VectorRunner.ts` with CPU-buffered feathering script and RGBA-safe FFmpeg fallback filter.

## Fix 6: UI Fixes (Stem Mixer Master Exclusion & Dynamic Titlebar Theme IPC)
- **Files:** `src/components/ripper/JobQueueList.tsx`, `electron/main.ts`, `electron/preload.ts`, `src/types/media.ts`, `src/store/useJobStore.ts`
- **Problems:** 
  1. Stem mixer played the full audio master rip on top of isolated stems (+6dB clipping).
  2. Windows titlebar buttons remained dark in Light mode on cold launch and theme switch.

### Replacement Instructions 6A (`JobQueueList.tsx`):
Filter out master track pills (`p.type !== 'audio'` & exclude master) so only isolated stems are mixed:
```typescript
  const stemPills = pills.filter(
    (p) =>
      p.type !== 'audio' &&
      p.type !== 'video' &&
      p.type !== 'proxy' &&
      (p.type === 'vocals' ||
        p.type === 'instrumental' ||
        p.type === 'drums' ||
        p.type === 'bass' ||
        p.type === 'other' ||
        (p.filePath.toLowerCase().endsWith('.wav') && !p.id.toLowerCase().includes('master')))
  );

  if (stemPills.length <= 1) return null;
```

### Replacement Instructions 6B (`main.ts`, `preload.ts`, `useJobStore.ts`):
Initialize titlebar overlay from `nativeTheme.shouldUseDarkColors` on startup, and implement the `window:set-theme` IPC channel:
```typescript
// In electron/main.ts:
ipcMain.handle('window:set-theme', (_event, theme: string) => {

  }
});
```

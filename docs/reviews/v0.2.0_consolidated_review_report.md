**Evaluation Target:** `docs/specs/v0.2.0_export_and_hardening_spec.md` and v0.2.0 Codebase Modifications  
**Review Type:** Goldfish Antagonistic Review Swarm (Uninterrupted Consolidated Protocol)  
**Personas Executed:**

2. **Naive Reader** (`egm-comprehension`): Plain readability, edge-case coverage, and definition gaps.

4. **Pragmatic Tech Lead** (`egm-implementation-readiness`): Code verification, test fidelity, and runtime safety.

## 1. Executive Summary & Verdict

The v0.2.0 update successfully satisfies the primary user request: routing single-file deliverables directly into the user's export folder with automatic numbering `(1)`, `(2)` while retaining isolated subfolders for multi-file deliverables. All four targeted hardening patches (Demucs WAV cleanup, silent video guard in silence detection, expanded audio extensions, and collision tests) are operational, and the binary compiles cleanly with zero TypeScript errors.

However, the antagonistic review swarm identified **3 Blockers** and **6 Major deficiencies** in production code that will cause data corruption, false file delivery, or event loop blocking under real-world usage:
1. **Prefix Match Bug in Direct Export**: In `YtDlpRunner.ts`, when direct export is active, `files.find(f => f.startsWith(chosenBaseName))` scans the user's shared export folder without extension verification. If an older `Clip (1).mp4` exists when downloading `Clip`, the older file is matched and reported to the UI as the new download. Non-media files (e.g. `Clip.info.json` or `Clip.docx`) can also be falsely matched.
2. **TOCTOU Concurrency Race Condition**: `getNonCollidingFilePath` only checks `fs.existsSync(candidate)`. Two concurrent jobs writing to the same destination with identical titles will both claim the same filename before either writes, causing silent overwriting or Windows `EBUSY` file locking errors.
3. **Passlog Event Loop Blocking & Error Leak**: In `FfmpegRunner.ts`, 2-pass CPU compression runs `fs.readdirSync(os.tmpdir())` after completion, blocking Node's event loop if the OS temp directory contains tens of thousands of files. Furthermore, if encoding fails or is cancelled, cleanup never runs.
4. **Test Suite Decoupling**: `tests/self-check.test.mjs` re-implements mock duplicates of `getNonCollidingFilePath` instead of importing production code, and omits the mandated Premiere Pro XML frame calculation unit tests.

## 3. Detailed Consolidated Findings

### 🔴 Blockers

#### EGM-01: False-Positive File Matching in Direct Export Mode
- **Affected File:** `electron/services/YtDlpRunner.ts` (lines 527–545)
- **Problem:** When `stemMode === 'off'`, `jobFolder` is `config.outputDir`. The post-download file finder runs:
  ```typescript
  let mediaFile = files.find(f => f.startsWith(chosenBaseName) && !f.endsWith('.part') && ...);
  ```
  1. If `config.outputDir` contains `My_Video (1).mp4` from an earlier download and the user downloads `My_Video.mp4`, alphabetical sorting matches `My_Video (1).mp4` because `"My_Video (1)".startsWith("My_Video")` is `true`.
  2. The code does NOT check `mediaExts` when `isDirectExport` is active. Non-media files like `My_Video.info.json` or `My_Video.docx` in the download folder are returned as the completed video.
- **Remediation:**
  1. Check `fs.existsSync(expectedOutputPath)` directly.
  2. If reading directory for container extensions, enforce exact stem match and whitelisted extension:
     ```typescript
     const parsed = path.parse(f);
     return parsed.name === chosenBaseName && mediaExts.has(parsed.ext.toLowerCase());
     ```

#### EGM-02: TOCTOU Concurrency Race Condition in File Name Resolution
- **Affected File:** `electron/services/FileUtils.ts` (lines 8–24)
- **Problem:** `getNonCollidingFilePath` only queries `fs.existsSync(candidate)`. When two downloads or batch conversions with the same title start concurrently, both check the disk before either writes. Both receive `destDir/Clip.mp4`. When FFmpeg or yt-dlp executes, one overwrites the other or crashes with `EBUSY`.
- **Remediation:** Maintain an in-memory `Set<string>` of active claimed file paths (`reservedPaths`) inside `FileUtils.ts`. `getNonCollidingFilePath` must check both `!fs.existsSync(candidate)` AND `!reservedPaths.has(candidate)`. Add candidate to `reservedPaths`, and export `releaseFilePath(path)` called in runner `finally` blocks.

#### EGM-03: Passlog Cleanup Leaks on Failure and Blocks Event Loop
- **Affected File:** `electron/services/FfmpegRunner.ts` (lines 981–1060)
- **Problem:**
  1. The 2-pass CPU encoding cleans up temporary passlog files inside the `else` block after `await runFfmpegWithProgress`. If Pass 1 or Pass 2 fails or is cancelled, cleanup never executes, permanently leaking files in `os.tmpdir()`.
  2. Cleanup calls `fs.readdirSync(os.tmpdir())`. In production environments with tens of thousands of temporary files, this synchronous call freezes the Electron main process event loop.
- **Remediation:**
  Delete the known specific files directly (`${passLogPrefix}-0.log`, `${passLogPrefix}-0.log.mbtree`) inside a `try...finally` block without scanning `os.tmpdir()`.

### 🟡 Major Findings

#### EGM-04: Test Suite Disconnected from Production Code & Missing XML Spec Tests
- **Affected File:** `tests/self-check.test.mjs`
- **Problem:**
  1. Unit tests test local copy-pasted implementations of `getNonCollidingFilePath` and `validateSilenceChopperAudio` rather than testing the real exports in `electron/services/FileUtils.ts`.
  2. Spec Patch D explicitly mandates: *"Unit tests for Premiere Pro XML sequence frame calculation rules."* This test was completely omitted.
- **Remediation:**
  1. Add tests validating sequence timebase frame conversion (`inFrame = Math.round(start * fps)`).
  2. Update tests to exercise `FileUtils.ts` directly against `node:os` temp directories.

#### EGM-05: Scattered Stem WAV Cleanup & Missing Pre-Demucs Normalization Guard
- **Affected File:** `electron/services/StemRunner.ts` (lines 75–100, 160–190)
- **Problem:** `cleanupTempWav` is declared after `extractOrNormalizeWav`. If extraction throws or is cancelled mid-stream, the partial WAV file leaks. Cleanup is manually called across 10 callbacks.
- **Remediation:**
  Wrap the entire execution from WAV extraction through Demucs separation in a single `try...finally` block that guarantees `cleanupTempWav()` is always called.

#### EGM-06: Windows Reserved Device Names and Trailing Dot/Space Failures
- **Affected File:** `electron/services/FileUtils.ts`
- **Problem:** If a user downloads a video titled `CON`, `PRN`, `AUX`, `NUL`, or `COM1`, Windows filesystems reject file creation with `EINVAL` or `EPERM`. Also, Windows silently drops trailing spaces and periods, causing `fs.existsSync` to fall out of sync with actual file creation.
- **Remediation:**
  Sanitize base names against reserved DOS device names and strip trailing spaces/dots in `FileUtils.ts`.

#### EGM-07: Orphaned `.part` and `.ytdl` Clutter on Direct Export Cancellation
- **Affected File:** `electron/services/YtDlpRunner.ts`
- **Problem:** When direct export writes to `config.outputDir`, cancelling a download leaves `${chosenBaseName}*.part` files directly in the user's root folder.
- **Remediation:**
  On job cancellation or error in direct export mode, delete matching `.part` and `.ytdl` files for `chosenBaseName`.

#### EGM-08: Number Suffix Stacking on Numbered Inputs
- **Affected File:** `electron/services/FileUtils.ts`
- **Problem:** If a video title already ends in a counter (e.g. `Tutorial (1)`), `getNonCollidingFilePath` generates `Tutorial (1) (1).mp4` instead of advancing the number to `Tutorial (2).mp4`.
- **Remediation:** Parse existing trailing `(N)` from `baseName` before incrementing.

#### EGM-09: Multi-File Stems Deep Nesting
- **Affected File:** `electron/services/StemRunner.ts`
- **Problem:** Demucs places outputs in `${jobFolder}/stems/htdemucs/${trackName}/vocals.wav`. The user has to click through three levels of folders to find their audio stems.
- **Remediation:** Flatten stem outputs directly into `${jobFolder}/Vocals.wav`, `${jobFolder}/Instrumental.wav`.

### 🟢 Nits

#### EGM-10: Empty `destDir` Guard
- If `destDir` is empty string `""`, `fs.mkdirSync` throws. Default to `process.cwd()` or `os.homedir()`.

#### EGM-11: Centralized Base Name Sanitization
- Move duplicate sanitize regexes from `YtDlpRunner`, `FfmpegRunner`, and `VectorRunner` into `FileUtils.sanitizeBaseName()`.

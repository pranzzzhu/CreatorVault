## 1. Executive Summary

The v0.1.2 UX update succeeds in replacing intimidating technical jargon with approachable creator language, adding draggable timeline windowing, dynamic download button text, and native Windows taskbar progress indication.

However, cross-persona synthesis identified **1 Blocker**, **5 Majors**, and **3 Nits**:
1. **Blocker:** Unconditional `--remux-video mp4` on YouTube 1080p fallback streams copies VP9 video and Opus audio into MP4 containers, breaking imports in Premiere Pro and DaVinci Resolve.
2. **Majors:**
   - Unhandled runner exceptions in Electron IPC leave the taskbar progress indicator frozen green forever.
   - An unmanaged 2500ms error timeout in `main.ts` prematurely resets active progress indicators when new jobs start.
   - React window event listeners in `TimeRangeSlider.tsx` thrash at 60Hz due to store updates in the `useEffect` dependency array.
   - Missing directory validation for paths loaded from `localStorage` risks runtime `ENOENT` failures when folders are deleted or unmounted.
   - Minimum duration clamping at `1.0s` inflates sub-second media and causes out-of-bounds handle positioning.

## 3. Detailed Findings & Concrete Remediation

### 🔴 EGM-01: Broken Edit-Ready NLE Guarantee for Fallback YouTube 1080p Streams
- **Files:** `electron/services/YtDlpRunner.ts` (lines 358–368)
- **Problem:**
  ```typescript
  args.push(
    '-f',
    `bestvideo[height<=${maxH}][ext=mp4][vcodec^=avc]+bestaudio[ext=m4a]/bestvideo[height<=${maxH}]+bestaudio/best`,
    '--merge-output-format',
    'mp4',
    '--remux-video',
    'mp4'
  );
  ```
  When YouTube does not provide an AVC video stream (common on modern 60fps uploads, vertical Shorts, and high-framerate clips), yt-dlp falls back to the second selector (`bestvideo+bestaudio`), downloading VP9/AV1 video with Opus audio in WebM. `--remux-video mp4` runs `-c copy` into MP4. Premiere Pro and DaVinci Resolve reject VP9/Opus in MP4 containers with "unsupported compression type".
- **Remediation:**
  Use separate selectors for native AVC vs fallback. In fallback mode, use `--recode-video mp4` so ffmpeg transcodes VP9/Opus into standard H.264/AAC MP4:
  ```typescript
  if (maxH >= 1440) {
    args.push(
      '-f', `bestvideo[height<=${maxH}]+bestaudio/best`,
      '--merge-output-format', 'mp4',
      '--recode-video', 'mp4'
    );
  } else {
    // Attempt instant remux for AVC streams; transcode non-AVC fallback to guarantee NLE playback
    args.push(
      '-f', `bestvideo[height<=${maxH}][ext=mp4][vcodec^=avc]+bestaudio[ext=m4a]/bestvideo[height<=${maxH}]+bestaudio/best`,
      '--merge-output-format', 'mp4',
      '--recode-video', 'mp4'
    );
  }
  ```

### 🟡 EGM-02: Unhandled Runner Exceptions Leaving Taskbar Progress Frozen
- **Files:** `electron/main.ts` (lines 315–371, 412–434, 459–476, 508–531)
- **Problem:**
  None of the four IPC start handlers (`job:start`, `fixer:start`, `vector:start`, `converter:start`) use `try ... catch ... finally`. When network errors, process aborts, or ffmpeg spawn failures occur, the promise rejects directly to the renderer without calling `mainWindow.setProgressBar(-1)`. The taskbar icon stays permanently green at partial progress.
- **Remediation:**
  Wrap handler executions in `try ... catch ... finally`:
  ```typescript
  ipcMain.handle('job:start', async (event, jobId: string, config: JobConfig) => {
    const emitProgress = (progressPayload: JobProgressEvent) => {
      updateWindowTaskbarProgress(progressPayload);
      event.sender.send('job:progress', progressPayload);
    };

    try {
      const dlResult = await ytDlpRunner.executeDownload(jobId, config, emitProgress);
      // ...
      return result;
    } catch (err) {
      updateWindowTaskbarProgress({ jobId, stage: 'error', progress: 100, statusMessage: (err as Error).message });
      throw err;
    }
  });
  ```

### 🟡 EGM-03: Unmanaged Error Timeout in Taskbar Progress
- **Files:** `electron/main.ts` (lines 300–313)
- **Problem:**
  ```typescript
  mainWindow.setProgressBar(1, { mode: 'error' });
  setTimeout(() => {
    if (mainWindow && !mainWindow.isDestroyed()) {
      mainWindow.setProgressBar(-1);
    }
  }, 2500);
  ```
  If a user starts another job or retries within 2.5 seconds, the unreferenced timer fires in the background and clears the active progress bar of the new job.
- **Remediation:**
  Store the timeout reference in `let errorResetTimer: NodeJS.Timeout | null = null;`. Clear it with `clearTimeout(errorResetTimer)` on every incoming progress event before setting new state.

### 🟡 EGM-04: High-Frequency Mouse Listener Re-binding in TimeRangeSlider
- **Files:** `src/components/ripper/TimeRangeSlider.tsx` (lines 71–116)
- **Problem:**
  ```typescript
  useEffect(() => {
    if (!draggingMode) return;
    const handleMouseMove = (e: MouseEvent) => { /* ... */ };
    window.addEventListener('mousemove', handleMouseMove);
    return () => window.removeEventListener('mousemove', handleMouseMove);
  }, [draggingMode, duration, startTime, endTime, onChangeRange]);
  ```
  `startTime` and `endTime` are mutated in Zustand on every mousemove. This triggers a React re-render, causing the effect cleanup to remove and re-attach `window` event listeners 60+ times per second during dragging.
- **Remediation:**
  Store `startTime` and `endTime` in a mutable ref (`latestRangeRef.current = { startTime, endTime }`). Omit them from the `useEffect` dependency array so the window listener binds once on mousedown and cleanly unbinds on mouseup.

### 🟡 EGM-05: Missing Directory Validation on `localStorage` Folder Path
- **Files:** `src/store/useJobStore.ts` (lines 179, 808), `electron/main.ts` (lines 247–260)
- **Problem:**
  `vortex_last_output_dir` in `localStorage` can point to deleted paths or unmounted external drives. In `main.ts`, `dialog:select-dir` checks `fs.existsSync(currentDir)`, which evaluates true for files as well as directories.
- **Remediation:**
  Check `fs.existsSync(startPath) && fs.statSync(startPath).isDirectory()`. If false, fall back to `getDefaultOutputDir()`.

---

### 🟡 EGM-06: Sub-Second Clip Inflation and Handle Clamping Bounds
- **Files:** `src/components/ripper/TimeRangeSlider.tsx` (lines 81–93), `src/store/useJobStore.ts` (lines 274–280)
- **Problem:**
  `windowSpan = Math.max(1, dragOriginRef.current.initialEnd - dragOriginRef.current.initialStart)` forces a minimum span of `1.0s`. For clips between `0.1s` and `0.9s`, dragging the window forcibly inflates duration to `1.0s`. Handle dragging logic (`endTime - 1` and `startTime + 1`) also pushes start times negative on clips under 1s.
- **Remediation:**
  Change minimum span to `0.1s`: `Math.max(0.1, initialEnd - initialStart)`. Clamp handle drag bounds dynamically against `Math.min(0.1, duration)`.

---

### 🟢 EGM-07 through EGM-09: Code Quality Nits
1. **Falsy Zero Progress:** Replace `(progressPayload.progress || 5)` with `(progressPayload.progress ?? 5)` in `electron/main.ts#L310`.
2. **Packaged App Fallback:** In `useJobStore.ts`, drop `'./exports'` fallback in favor of `state.diagnostics?.defaultOutputDir`.
3. **Unconditional Fragments Flag:** In `electron/services/YtDlpRunner.ts`, remove redundant `--concurrent-fragments 4` from the `else` branch and specify it once unconditionally.

## 4. Remediation Plan

1. **Step 1:** Fix `--recode-video mp4` fallback in `electron/services/YtDlpRunner.ts` to protect NLE compatibility.
2. **Step 2:** Wrap IPC runner handlers in `electron/main.ts` with `try / catch` to clear taskbar progress on exceptions, and add `clearTimeout(errorResetTimer)` to eliminate timer races.
3. **Step 3:** Optimize `TimeRangeSlider.tsx` mousemove listeners using refs and reduce minimum window span to `0.1s`.
4. **Step 4:** Add `isDirectory()` validation in `electron/main.ts` for directory picker default paths.
5. **Step 5:** Run `npx tsc --noEmit` and `npm test` to verify build integrity.
